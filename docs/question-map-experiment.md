# 질문 지도 실험 페이지

50명 청중 시뮬레이션: 지도에만 가상 150핀(1인 3개)을 기본 표시, OFF로 원래 데이터 복귀.
2페이지에 최소 50핀을 배치하여 밀집도를 확인한다. 가상 완료는 메모리에서만 처리,
simulation-audience- ID는 persistence 호출 전에 분기한다. 새로고침 시 초기화.
이는 합성 UI 데이터이며 실제 50명 동시 접속 부하 테스트가 아니다.

2026-09-29 승인된 제안 구현: 저장된 영역 고정 표시, 필터 일치 PIN 강조 및 나머지 흐리게 표시.
영역별 선택 유형 미처리 수/전체 미처리 수 구분. 원문 앞뒤 이동은 클릭 시 ID 순서를 유지하여
완료 후에도 질문을 건너뛰지 않는다. 영역 밖/중첩은 미지정. 영역이 없으면 편집 안내, AI 자동 분할 없음.

2026-09-29 사용자 요청: 클릭 카드의 이미지 bounds에서 전체화면으로 320ms 확대.
prefers-reduced-motion에서는 생략. 지도 말풍선은 180ms 확장(다른 화면 기본값 보존).
말풍선은 질문 원문/답변 처리 버튼만 표시. 기존 completeGroup으로 resolved 처리하며
텍스트 답변을 만들거나 전송하지 않는다. DB 성공 후 흰색 미처리 PIN을 파란색으로 변경.
색상은 지도에만 적용하며 처리 상태 버튼으로 텍스트도 제공. 오류와 기존 되돌리기 유지.

검증: 타입/production build 성공, 지도 모델 테스트 10개 통과. 로컬 DB read-only로
완료/취소 RPC 존재 확인. 실제 상태 변경 및 브라우저 애니메이션 검증은 미실시.
이번 변경의 ESLint는 장시간 완료되지 않아 중단했으며 통과로 간주하지 않는다.

2026-09-29 핀 중심 질문 열기: 카드의 질문 열기 버튼과 별도 질문 목록 패널 제거.
전체화면에서 기존 SlideCanvas와 QuestionDetailDialog/PinComposer를 재사용하여
원래 핀 아이콘, 핀에서 확장되는 몸체, 좌표를 가리키는 꼬리, 외부 클릭 닫기를 유지.
섹션 설정은 영역 편집으로 분리하여 기존 저장 데이터 보존. 전체화면은 portal로
캔버스 도구의 버튼 스타일 간섭을 차단한다. 운영 DB 변경 없음.

2026-09-29 사용자 요청: 페이지 단일 클릭 시 뷰포트를 채우는 슬라이드 대화상자.
핀/필터 유지, 닫기 및 Esc 복귀, 드래그는 기존 배치 이동 유지. 운영 데이터 변경 없음.

## 화면 맞춤 배치 (2026-09-29 사용자 요청)

그룹을 세로로만 쌓지 않고 가용 화면 비율에 맞춰 좌우로 배치한다.
여러 열 수/줄바꿈 후보 중 전체 표시 배율이 가장 큰 배치를 사용한다.
상단 도구/필터와 하단 줌 도구의 공간은 제외한다. 재배치 애니메이션과 원본 좌표는 유지.

## 자유 캔버스 개정 (사용자 요청)

대시보드 스타일을 폐기하고 Figma/Prezi식 공간 탐색으로 변경한다. 새 페이지에만 독립 색상/스타일 적용.
빈 공간 드래그로 pan, 휠로 포인터 중심 zoom, 카드 드래그로 자유 배치, 더블클릭/버튼으로 집중 확대.
기준 변경 시 같은 DOM 카드가 좌표 보간으로 이동한다. 새 질문은 배치를 자동 변경하지 않는다.
위치 변경은 화면 전용이며 원본 slide 순서/PIN 좌표/DB에는 저장하지 않는다. 전체 보기로 복귀 가능.
질문 상세는 우측 플로팅 패널로 열어 캔버스에서 벗어나지 않는다. 기존 질문 처리 계약 유지.

자유 캔버스 검증: 줌 포인터 고정/배율 제한/그룹 좌표 테스트 3개 통과, 타입 및 변경 파일 lint 통과.
페이지 HTTP 200. 브라우저 도구는 같은 kernel assets 오류로 실행 불가하여 시각/터치 실검증은 미완료.
키보드는 캔버스에 포커스 후 방향키 이동, +/- 확대 축소, 0 전체 보기 지원.

2026-09-29 사용자 요청 승인: 자료 카드에 별도 진입 버튼, 기존 발표 UI와 독립된 페이지.

- 실제 소유 세션의 슬라이드와 질문을 사용. 기존 admin guard / 저장 RPC 재사용.
- 원래 순서, 처리 상태, 질문 유형으로 그룹화. 정렬 기준 변경/명시적 갱신에만 FLIP 재배치.
- 카드 안 페이지 번호/정규화 PIN 좌표 유지. 질문 변화는 수치만 반영하고 배열은 고정.
- 페이지 확대, 직접 사각형 섹션 지정 및 명칭/삭제, 영역별 유형 건수/원문 표시.
- 섹션은 실험용 개인 화면 설정이며 계정+세션+슬라이드 ID별 브라우저에만 저장.
  질문 원문/상태의 권위 데이터는 DB이며 섹션의 서버 공유는 후속 범위.
- 모르겠어요는 명시 카테고리와 보수적 문구 일치를 구분. AI 판정이라고 표시하지 않음.
- 제외함은 기존 deferred 보류와 동일, DB 저장. 원문 삭제 없음. 완료/취소/공통 답변 재사용.
- 모바일 카드 좌우 스와이프 및 동일 버튼, 처리 완료는 이해 확인 또는 자동 답변 전송 아님.
- 운영 DB 접근/마이그레이션/원본 PPT 순서 변경 없음. 사용자 데이터 보존 위해 DB reset 안 함.
- 페이지별 선택은 기존 발표 화면으로 링크 가능, 발표 중 페이지를 자동 변경하지 않음.

검증: 순수 집계/좌표/분류/영역 경계 테스트, 타입/lint/build. 브라우저 검증 결과 별도 보고.

## 이번 구현 검증

- 질문 지도 모델 테스트 6개 통과. 변경 파일 ESLint 통과.
- production build 성공, 새 route 등록 확인. 로컬 route HTTP 200 확인.
- 브라우저 자동화 런타임이 `failed to write kernel assets`로 시작하지 못해
  화면/터치/실제 재배치 동작의 시각 검증은 미완료. HTTP 응답을 UI 검증으로 간주하지 않는다.
- 기존 질문 처리 hook과 DB RPC를 재사용. 본 턴에는 실제 질문 상태를 시험 변경하지 않았다.
- 현재 섹션은 수동 지정이며 AI 영역 분할/자동 요약은 포함하지 않는다.
- 위치가 없는 질문의 공통 답변은 기존 hook의 슬라이드 확인 제한을 따르며,
  모바일 완료/제외와 별개다. 제외함은 기존 보류 목록과 연동한다.
- 설명 시작/설명 후 반응 집계, 잘못된 PIN 위치 수정, 서버 공유 섹션은 후속 구현 범위다.
- 사용자 원본 DB 초기화, 운영 DB 접근, GitHub push는 수행하지 않았다.

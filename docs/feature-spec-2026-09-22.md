# ClassPin 기능명세서 (2026-09-22)

- 기준: `Team-Newdawn/ClassPin-FE` `AI_Develop` 브랜치 + 아직 커밋하지 않은 로컬 변경
- 실행 환경: 로컬 개발 전용 (Next.js 127.0.0.1:3000, Docker 로컬 Supabase, AI 는 이 PC 의 CPU 로컬 모델). 운영에는 배포하지 않았다.
- 상태 표기: 완료 = 화면까지 동작 확인, 부분 = 동작하지만 제한이 큼, 제안 = 명세만 있고 구현 전
- 공유 문서(같은 내용): https://claude.ai/code/artifact/aa6100a4-7020-4a88-ad9d-35563801f29b

| 역할 | 들어오는 방법 | 주요 화면 |

| 참여자 | QR·참여 코드, 익명 로그인 | `/join/[code]` |

## 1. 참여자 기능

| 기능 | 동작 | 상태 |
|---|---|---|
| 입장 | QR 또는 8자리 참여 코드 → 익명 로그인. 종료된 세션은 "세션이 종료되었어요" | 완료 |
| 슬라이드 따라가기 | 강사 페이지를 따라가고, 이전 페이지를 보다가 "현재 슬라이드로" 복귀 | 완료 |
| 직접 PIN 질문 | 슬라이드를 눌러 위치 → 카테고리·PIN 모양·내용(선택) | 완료 |
| 글로 질문 (AI 위치 찾기) | "실시간 질문" 아래 입력칸에 문장만 쓰면 페이지·영역·좌표·카테고리를 정해 PIN 생성 (3장) | 부분 (분석 캐시가 있는 SOi 15쪽만) |
| 위치 확인 | 신뢰도 70% 미만이면 "이 위치가 맞나요?" — PIN 끌기/슬라이드 클릭, 다른 후보, 카테고리 선택 후 등록 | 완료 |
| 중복 질문 안내 | 같은 질문이 있으면 먼저 보여 주고 👍 공감으로 대신. 내 질문·답변 완료 질문은 표시만 | 완료 |
| PIN 옮기기 | 답변 전 내 질문을 다른 위치·페이지로 이동 (RPC `move_own_question_pin`) | 완료 |
| 질문 수정·삭제 | 내 질문의 카테고리·내용 수정, PIN 삭제 | 완료 |
| 공감 | 남의 질문에만. 5개 이상이면 🔥 | 완료 |
| 이모지 반응 | 👍 ❓ 💡 🙁 — 강사 화면·슬라이드쇼에 실시간 표시 | 완료 |
| 질문 목록 | 공감순·최신순, 강사 답변 표시, 목록 숨기기 | 완료 |
| 종료 후 설문 | 세션이 끝나면 플랫폼 경험 설문으로 이동 | 완료 |
| 하단바 (화상회의형) | 페이지·LIVE 따라가기, 반응, 질문하기(PIN/글), 더보기(전체 화면·참여 코드·언어), 나가기 · 오른쪽 질문 목록 + 새 답변 알림 | 완료 (실제 세션 화면 확인 전) |

- 실시간 반영: Realtime 이벤트 + 2초 스냅샷 확인. RLS 때문에 남의 질문 변경 이벤트가 안 올 수 있어 스냅샷으로 보정한다.
- 알려진 제약: 질문 목록을 숨기면 글로 질문하는 입력칸도 함께 숨는다 (6장 제안 4).

## 4. AI 질문 위치 자동 배치

서버는 판단만 하고 DB 에 쓰지 않는다. PIN 저장은 참여자 브라우저가 기존 질문 등록 경로(RLS)로 한다.

| 단계 | 하는 일 |
|---|---|
| 1. 문맥 | 라이브 강의, 최신 자료 버전의 슬라이드, 켜진 카테고리, 기존 질문(최대 300개)을 참여자 권한으로 읽음 |
| 2. OCR·영역 | 이미지 checksum 으로 PP-OCRv5 글자·PP-DocLayoutV3 영역을 찾아 제목·본문·그래프·표·그림·설명 문구 영역 생성 (머리말·쪽번호·꼬리말 제외) |
| 3. 질문 단서 | 페이지 번호, 요소 종류, 좌우·위아래, "두 번째 행", 숫자, 내용 단어, "이거/여기", 색상 |
| 4. 검색 | 글자 일치 + Qwen3-Embedding-0.6B 의미 유사도 |
| 5. 페이지 규칙 | 적힌 페이지 > 현재 페이지 > 다른 페이지 (다른 페이지는 근거가 강하고 현재 페이지가 약할 때만, "이거/여기"면 현재 페이지 유지) |
| 6. 좌표 | 숫자·단어가 나온 줄, 표의 n번째 행, 없으면 영역 가운데 |
| 7. 카테고리 | 질문 의도로 켜진 카테고리 중 하나 |
| 8. 중복·연관 | 글자·의미 유사도 + 같은 영역 여부 |
| 9. 신뢰도 | 1·2위 차이, 내용 일치, 종류·위치 일치, 유일한 종류, 페이지 일치. 단서 없으면 ≤35%, 색상만 ≤68% |
| 10. 결정 | ≥70% 자동 생성, 미만이면 확인 카드 + 백그라운드 Qwen3 4B 재확인 |

- 모델: Qwen3-Embedding-0.6B Q8_0 (상주, 20분 미사용 시 종료), Qwen3-4B-Instruct Q4_K_M (재확인 때만). llama.cpp, CPU, 외부 API 0원.
- 재확인 건너뛰기: 단서 없는 질문과 이미 70% 이상인 결과는 LLM 을 띄우지 않는다.
- API: `POST /api/dev/question-placement` (mode = fast · refine · warmup), 로컬 개발 서버 + 로컬 Supabase + 익명 참여자 토큰일 때만.
- 오프라인 평가(글자 검색만): 실제 질문 17개 중 페이지 17/17, 영역 8/16, 틀린 자동 배치 0건.
- 제한: 분석 캐시가 있는 자료만, 색상은 판단 불가, 그림 속 내용은 설명 문구가 있어야 찾음.

## 5. 그 밖의 AI 기능

| 기능 | 어디서 | 모델·비용 | 동작과 한계 |
|---|---|---|---|
| 강사 AI 추천 답변 | 강사 세션, `POST /api/dev/live-pin` | 로컬 Qwen3 4B | 페이지 OCR 근거 한 문장 분석·두 문장 초안·OCR 원문 인용. 인용이 OCR 에 없으면 실패 처리. 수십 초, 동시에 하나 |
| AI 강사 리포트 | 폴더 인사이트, `/api/admin/ai-reports` | OpenRouter 생성 + 다른 계열 검토, 비용 확인·상한 | 운영 Supabase·Cloud Tasks 설정이 있어야 동작, 이번 로컬 테스트 범위 밖 |
| 모델 비교 실험실 | `/admin/ai-reports/[id]/experiment`, `/dev/model-benchmark` | OCR 3 × 레이아웃 3 × LLM 3 (로컬) | 개발자용 비교 화면. 여기서 고른 결과가 AI 위치 찾기의 분석 캐시 |

- 추천 답변·위치 재확인·실험실은 같은 CPU 잠금(`output/model-lab/inference.lock`)을 쓴다. 하나가 돌면 나머지는 바로 건너뛴다.
- 모델 파일 sha256 은 크기·수정 시각이 같으면 한 번만 계산한다.

## 6. 데이터·권한·API

| 테이블 | 내용 | 참여자 권한 (RLS) |
|---|---|---|
| `courses` → `lectures` | 강의, 상태, 현재 페이지, PIN·QR 설정, 카테고리 | 진행 중 강의만 읽기 |
| `materials` → `material_versions` → `slides` | 자료, 버전, 페이지 이미지·checksum | 진행 중 강의 자료만 읽기 |
| `region_anchors` | PIN 좌표 (참여자는 point, 0~1) | 본인 점만 |
| `questions` | 본문 1~300자, 카테고리, PIN 모양, 상태, 공감 수 | 등록, 답변 전 본인 질문 수정·삭제. 남의 질문은 RPC `find_lecture_questions` 로만 |
| `question_reactions` | 사용자별 공감, trigger 로 `reaction_count` 유지 | RPC `set_question_reaction` 으로만 |
| `answers` | 강사 답변 | 읽기만 |
| `ai_reports` 외 6개 | AI 리포트 작업·결과·비용 | 없음 |

- 새 migration `20260921201500_participant_move_question_pin.sql`: `move_own_question_pin(질문, 슬라이드, x, y)` — 본인·미답변·강의 진행 중·같은 자료 버전·좌표 0~1 일 때만. 로컬 DB 에만 적용.
- `/api/dev/*` 는 `NODE_ENV=development`, 요청·Supabase 주소가 모두 로컬, 같은 출처일 때만 응답(아니면 404). 서비스 키는 쓰지 않고 요청자 토큰으로 RLS 를 거친다.

## 7. 검토 후 바로 수정한 것

| 문제 | 수정 | 파일 |
|---|---|---|
| 강사 화면에 PIN 표시를 토글하는 스위치가 두 개 | "PIN 알림" 버튼 제거, 위쪽 스위치로 통일 (끌 때 알림도 닫음), 설명 수정 | `admin/session/[id]/page.tsx` |
| "PIN ON · 질문 시간"이 PIN 을 켜는 것처럼 보임 | "질문 시간 시작 · TOP 5" | 같은 파일 |
| 단서 없는 질문도 Qwen3 재확인 → CPU 잠금 1~2분 | 단서 없음·이미 70% 이상이면 재확인 생략 (화면·서버) | `question-placement.ts` ×3, `use-ai-question.ts` |
| 강사 AI 답변이 요청마다 2.5GB 모델 sha256 재계산 | 크기·수정 시각 기반 검증 캐시를 공용 모듈로, 두 스크립트에 적용 | `model_verification.py`(신규), `live_pin_answer.py`, `question_placement_llm.py` |
| 첫 AI 질문 때 기존 질문 최대 300개 임베딩 → 15초 초과 위험 | 페이지 ±1·미답변 우선 120개만 임베딩 | `server/question-placement.ts` |
| 재확인 후 중복 판단에서 의미 유사도 누락 | 같은 임베딩 유사도 전달 | 같은 파일 |
| 확인 카드에서 카테고리 변경 불가 | 카테고리 선택 상자, 직접 고른 값 유지, 완료 카드에 실제 카테고리 | `ai-question.tsx`, `.module.css`, `use-ai-question.ts`, `join/[code]/page.tsx` |
| 중복 안내에서 공감 버튼이 없는 이유 불명 | "내 질문", "답변 완료" 표시 | `ai-question.tsx` |
| 참여자 스냅샷 요청이 겹치고, 잠긴 휴대폰에서도 2초마다 요청 | 진행 중이면 한 번만 예약, 백그라운드 탭은 쉬고 복귀 시 즉시 확인 | `_controller/session-store.tsx` |
| 슬라이드쇼 PIN 공개 간격 주석이 값과 다름 | 주석 수정 | `present/controller.ts` |

- 검증: 클라우드에서 `npm ci` 후 `tsc --noEmit` 통과, 바뀐 파일 ESLint 0건, `node --test` 14개 파일 통과, 모델 검증 캐시 단위 확인.
- 기존 경고: `experiments/semantic_regions/test_live_pin.cjs` 의 `require()` ESLint 오류 5건은 이전부터 있던 것.
- `tmp/pin-sync-qa.cjs` 는 없어진 "PIN 알림" 버튼 대신 PIN 스위치를 찾도록 고쳤다.

# Local semantic sections

Run from the repository root on the existing Windows environment:

```powershell
.local/model-benchmark-venv/Scripts/python.exe -m uvicorn server:app --app-dir services/local-sections --host 127.0.0.1 --port 8769
```

- PP-OCRv5 reads text; PP-DocLayoutV3 detects elements; local Qwen3-4B groups element IDs with coarse/normal/fine caps of 3/6/10 topics. Coordinates are calculated from actual element boxes, not generated by the LLM.
- The model does not directly understand image pixels. Image-only slides fail for insufficient text rather than receiving fabricated semantic sections.
- Model downloads are disabled. Existing pinned models and verified GGUF are required. No paid or external inference API is used.
- Upload asks for lecture analysis settings first. Completion starts browser-driven sequential analysis, then instructor review at `/admin/session/[id]/analysis`. Only confirmed regions feed the section question panel. A closed browser interrupts remaining pages; reopen review and retry. This is not a durable production job queue.
- FastAPI accepts local browser origins only and one request at a time. Inputs are limited to 8 MB and 16 million pixels. Overlapping output sections fail validation.
- Extracted elements are cached under `.local/semantic-sections-v1` by image hash; semantic output is recalculated with the current config. Draft and confirmed results are separate browser snapshots. No database writes are added.
- The UI shows automatic output as requiring review. Legacy SOI Studio fixtures remain for unmanaged demos; once review configuration exists, Studio uses its confirmed snapshot instead of those fixtures.
- This is a local Windows prototype using existing model helpers, not a portable Docker deployment. Source images must be local; remote image URLs are refused.

## Semantic question grouping (local prototype)

`POST /question-groups` uses local Qwen3-4B to group one page's question texts
with the names/descriptions of regions containing each pin. It does not use
exact text matching and does not mark questions answered. The canvas action
“의미·맥락으로 질문 묶기” runs pages sequentially; results live in browser memory
only and are invalidated when source questions or region contexts change.
Unanalysed/failed pages retain individual questions; the blue count shows an ellipsis.
Results are AI suggestions requiring instructor review. No DB writes or external
inference are involved. Requests are limited to 150 questions and 18,000 input
characters per page; oversized or invalid outputs fail rather than dropping questions.

Real smoke test (6 synthetic Korean questions): approximately 32.95 seconds,
groups `[[0,1],[2,3],[4],[5]]`. Paraphrases merged, source requests stayed separate
from reason requests, and identical vague text in different regions stayed separate.
This is not a full-deck quality benchmark or a browser end-to-end verification.
Run: `.local/model-benchmark-venv/Scripts/python.exe services/local-sections/test_semantic_smoke.py`.

Actual local smoke test: SOi slide 5 returned HTTP 200 in 132,468 ms,
but merged the interview, insight and solution into one region. This verifies
execution only, NOT the requested semantic segmentation quality. Earlier runs
failed JSON/membership validation. Do not treat this prototype as production-ready
or as a validated replacement for manually reviewed sections. Full-deck quality
and upload UI end-to-end testing remain outstanding.

### 2026-09-29: 54~57개 질문 페이지의 422 진단 (Claude)

- `/question-groups` 실패 시 서버 콘솔에 `question-groups failed <오류 유형> <사유 160자>` 를 남긴다 (`/sections` 와 같은 정책, HTTP 본문은 그대로 `SEMANTIC_GROUPING_FAILED`). 성공 시에는 `question-groups ok n= groups= repaired= promptTokens= completionTokens= elapsedMs=` 를 남긴다. 질문 문장은 어느 쪽에도 찍지 않는다.
- 모델 출력 `assignments` 는 이제 "같은 묶음" 관계(union-find)로 읽는다. 프롬프트는 "묶음의 가장 앞 질문 번호"를 요구하지만 4B 모델은 다른 구성원 번호(i→7, 7→3)를 자주 써서 이전 엄격 검사(`values[v]==v`, `v<=i`)에 걸렸다. 두 표기 모두 "i와 7은 같은 묶음"이므로 가장 앞 번호로 정규화하고, 고친 포인터 수를 `repairedAssignments` 로 돌려준다. 길이 불일치·정수 아님·범위 밖은 여전히 실패다. 순수 테스트: `.local/model-benchmark-venv/Scripts/python.exe services/local-sections/test_question_groups.py` (6개).
- 재현: 서버를 띄운 뒤 `node --experimental-strip-types experiments/question-grouping/question-groups-repro.mjs --page 2` 를 실행하면 지도 화면의 50명 시뮬레이션 2페이지 요청(57문항, 접두어 제거 시 5종, 약 5.8k자)을 그대로 보낸다. `--dry` 는 전송 없이 요약만, `--limit N` 은 앞 N개만 보낸다.
- 원인 확정 상태: 코드상 크기 제한(150건, 18,000자, 128KB)은 이 요청에 걸리지 않는다. 남은 후보는 (1) 엄격 partition 검사 실패, (2) llama-server 기동/응답 지연, (3) 응답 JSON 미완성이며, 위 로그로 구분된다. 이 PC의 Windows 쪽에서 아직 실행하지 않았으므로 **확정 전**이다. `repaired>0` 으로 성공하면 (1)이 원인이었다는 뜻이다.

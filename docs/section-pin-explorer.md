# 강사용 Section → Cluster → Raw Pin 시각화

## 요청 및 구현 계약

2026-10-06 사용자 첨부 요구사항에 따른 로컬 프런트엔드 확장. 기존 강사 라이브/발표의 `ClusteredSlide`와 확정 섹션, SectionQuestionCluster를 재사용한다. 운영 DB·API·참여자 제출 구조는 변경하지 않는다.

- 확정 섹션이 있으면 섹션 개요를 기본으로 표시. 기존 가까운 핀 보기로 전환 가능.
- 섹션별 색·번호·이름·질문 수를 표시. 0건도 표시하며 섹션 미지정 질문은 별도 목록으로 보존.
- 섹션 선택 → 같은 섹션의 질문 클러스터 → 선택 클러스터의 실제 원문 좌표. breadcrumb와 Escape는 한 단계 위로 이동.
- 원문 좌표는 절대 변경하지 않는다. 클러스터 표시점만 centroid→섹션 내부 clamp→충돌 회피. 밀집한 원문은 겹침을 허용하되 목록에서 각각 선택 가능.
- 같은 질문 집계 결과로 마커·상세·숫자를 계산한다. 부모 visibleQuestionIds와 내부 상태/유형 필터를 교차 적용. 우선순위·작성자 정보는 기존 DTO에 없어 생성하지 않는다.
- 처리 완료는 기존 completeGroup/undoGroup을 이용. AI 답변 생성 아님. 오류를 노출하고 중복 요청을 방지한다.
- 섹션 없는 자료는 검수 링크와 미지정 질문 목록. 임의 섹션 생성 금지.
- 현재 섹션/의미 분석 저장은 기존 로컬 저장 계약을 그대로 사용. 다중 기기 서버 저장은 별도 과제.

## 검증 계획

순수 selector: 2/5/0/9 집계, 필터 보존, centroid/clamp/충돌, null 좌표와 20개 중첩. 브라우저: 3단계·뒤로가기·필터·완료/되돌리기·실시간 질문·페이지 전환·빈 섹션·좁은 화면. 타입 검사·대상 린트·빌드와 기존 핀 동작 회귀. 운영 DB reset은 데이터 손실 방지를 위해 수행하지 않는다.

## 구현 결과 및 검증 기록

### 2026-10-06 중복 정리 (사용자 승인: 진행해)

- `SectionQuestionPanel` 미사용 컴포넌트를 제거했다. 아래 최초 구현 기록보다 이 절의 변경이 우선한다.
- 섹션별 집계가 별도 0.88 엔진 대신 `condenseQuestions`를 호출한다. 질문 지도/목록도 확정 섹션을 우선 사용한다. 같은 페이지·섹션·질문 유형만 병합하며 확정 영역 0.82 / 미지정 0.90, 수동 separate는 단독 유지한다. 확정 섹션 없는 구형 지도는 기존 영역 fallback을 유지하므로 그 경우까지 화면별 동일 결과를 보장하지 않는다.
- 기존 triage 조회를 재사용하고 5초 갱신 및 저장 성공 이벤트를 반영한다. 실패/초기 로딩 중에는 개별 표시해 수동 분리 설정을 무시한 병합을 막는다. DB/권한/API 스키마는 변경하지 않았다.
- 라이브 화면에서 상세 패널은 기존 오른쪽 패널로 portal 렌더링한다. 기존 목록·필터·묶음 처리 UI와 동시에 표시하지 않는다. 발표 화면은 자체 패널을 유지한다. 기존 목록 보기로 돌아가면 목록의 독립 카테고리/정렬 상태는 보존된다. 카테고리와 AI 질문 유형은 의미가 달라 같은 값으로 강제 변환하지 않았다.
- 공간 기준 버튼은 ‘겹친 핀 접기’로 변경했다. 공간 접기는 표시 혼잡 해소이고 의미 묶음 수와 같지 않다.
- `test-shared-question-grouping.cjs`는 임계값, 섹션/유형 경계, 수동 분리, 동일 문구를 검증한다. 브라우저 테스트에 단일 오른쪽 패널·필터 표시와 기존 보기 복귀를 추가했다. 운영 triage/RLS 통합 검증은 하지 않았다.

1. 변경 파일: `app/component/clustered-slide.tsx`, `clustered-slide.module.css`. 신규 파일: `app/component/section-pin-explorer.tsx`, `section-pin-explorer.module.css`, `app/_controller/use-section-pin-explorer.ts`, `app/_model/section-pin-explorer.ts`, `scripts/test-section-pin-explorer.cjs`, `scripts/verify-section-pin-explorer.cjs`, 본 문서.
2. 신규 화면 컴포넌트는 SectionPinExplorer. 기존 강사 라이브 및 발표 ClusteredSlide에 통합했다.
3. Summary는 확정 bbox 내부 상단 중심 부근에 1개 표시한다. 0건 포함, 100건 이상 99+. 실제 질문 위치를 의미하지 않는다는 문구를 표시한다.
4. Cluster는 유효 좌표 평균→bbox 내부 clamp→48px 간격 후보 탐색. 이동했으면 원래 중심과 연결선을 그린다. 작은 영역에서는 완전 충돌 회피가 보장되지 않는다.
5. Raw는 normalized 원래 좌표 그대로 표시한다. 겹침을 허용하고 번호가 있는 원문 목록에서 개별 선택한다. 좌표 없는 질문은 목록에는 남긴다.
6. 선택 Section/Cluster/Question ID와 필터를 hook에서 관리하며 유효한 선택에 따라 3단계를 파생한다. breadcrumb/Escape로 상위 이동한다.
7. 패널은 페이지 요약→섹션별 유형 분포/묶음→대표 질문/원문/시간/좌표로 전환한다. 기존 완료/되돌리기 액션을 사용한다.
8. 유형·처리 상태 필터를 동일 집계에 적용한다. 발표 화면은 기존 순차 공개 visibleQuestionIds도 적용하므로 아직 공개되지 않은 핀은 집계에 들어오지 않는다.
9. 현재 페이지 데이터와 memoized 집계를 이용한다. 개요에서 raw를 렌더링하지 않고, 선택 묶음만 펼친다. 분석은 debounce/abort/stale-key 방어를 사용한다. 대규모 성능 벤치마크는 미실시.
10. 순수 helper 테스트, TypeScript, 대상 ESLint, production build 성공. 격리 Chromium의 고정 fixture에서 개요, 4/3/1 묶음, raw4, 완료/undo, why 필터, Escape, 중첩20, 라이브/발표 진입을 검증했다. 의미 분석 API는 테스트에서 unavailable 응답으로 대체했으므로 실제 모델 품질을 검증한 것은 아니다. 900/600 폭에서 컴포넌트 내부 overflow 검사 통과. 다만 전체 강사 화면의 기존 고정 사이드바는 모바일에서 가림을 유발하며 모바일 완료로 간주하지 않는다. 신규 질문 스트리밍/페이지 전환 전 시나리오를 별도로 자동 검증하지는 않았다.
11. 기존 데이터에 없는 priority/익명 작성자는 만들지 않았다. 섹션은 기존 로컬 확정 결과에 의존한다. 임베딩 연결이 없으면 동일 문구 기준만 사용하고 화면에 안내한다. 5색 이후 번호·테두리 패턴으로 보조 구분한다.
12. 후속 개선: 강사 전체 레이아웃 모바일 정리, 초밀집 핀 spiderfy, 섹션 요약 마커 간 전역 충돌 회피, 서버 저장/다중 기기 동기화, 실제 모델 및 실시간 대량 유입 검증.

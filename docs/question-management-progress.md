배경: 지도 화면의 파란 큰 핀(`use-semantic-groups.ts`)은 페이지 단위로 Qwen3-4B에 한 번에

- **1단계 규칙 접기** `app/_model/question-condense.ts` (순수 함수, DB·LLM 없음).
  같은 페이지 + 정규화 문구(`questionKey`: 접두어 제거, NFKC, 소문자, 끝 문장부호·공백 제거) 동일 → `exact`.
  ‘잘 모르겠어요/이해가 안 돼요’류 일반 신호 질문(`isGenericQuestion`, 숫자·영문 포함 시 제외)은
  (페이지, 영역, 의도) 기준으로 접고, 영역 정보가 없으면 핀 거리 0.06 이내끼리만 접는다 → `signal`.
  `triage.separate`, 핀 없음, 본문에 적힌 페이지와 핀 페이지 불일치는 단독 잠금.
- **2단계 임베딩 증분 묶기**: 신호 질문이 아닌 묶음끼리 코사인 유사도로 complete linkage
  (묶음의 모든 쌍이 기준 이상일 때만, 가장 유사한 쌍부터) 합친다. **0.90 이상은 바로, 0.82 이상은
  같은 영역(비어 있지 않은)일 때만**. 대표 질문은 의미 묶음이면 가장 중심에 가까운 질문, 아니면 가장 오래된 질문.
  묶음 `id`는 가장 오래된 원문 id로 고정해 기존 답변/보류 계약을 유지한다.
- 서버: `questionVectorsWithin(texts, budgetMs)` (`question-placement.ts`)이 기존 임베딩 서버·캐시를 재사용해
  예산 안에서 8개씩 벡터를 만들고 남은 건수를 돌려준다. 임베딩 서버가 idle이면 워밍만 시작하고 즉시 반환.
- 라우트 `POST /api/dev/question-similarity` (`labLocalRequest` + `requireAdminRequest`, 로컬 전용):

  유사도 ≥0.7인 간선, `pending`, `embedding` 상태. DB 쓰기 없음.

- 통합: 지도 파란 핀 수 = 축약 묶음 수(‘의미·맥락으로 질문 묶기’ 버튼 제거, 상태 문구로 대체),

## 구현

1. **선접수**: 원문을 `receive_question` RPC로 먼저 저장. 위치 없으면 좌표 null.
   요청 UUID + 원래 payload + 작성자를 확인해 동일 요청 재전송은 같은 질문을 반환한다.
   PIN 좌표와 질문 생성은 한 트랜잭션이다. AI 실패/취소는 원문을 지우지 않는다.
   분석 후 `move_own_question_pin`으로 기존 질문에 위치를 붙인다.
2. **묶음**: 동일 문구·페이지·카테고리·근접 PIN(정규화 거리 0.06 이하)을 모두 요구.
   모든 기존 멤버와 일치해야 하므로 연쇄 병합을 막는다. 모호한 표현·위치 미확정은 분리.
   DB 원문을 병합/삭제하지 않고 표시용 그룹을 계산한다. 의미 임베딩/LLM 요약 아님.
3. **강사 화면**: 오른쪽 ‘질문 묶음으로 처리하기’를 펼친다.
   원문 펼치기, 대표 질문 답변, 보류/복귀, 개별 분리/재적용, 묶음 완료/최근 완료 취소.
   보류/분리 결정은 DB에 보존. 완료는 눌렀을 때의 원문 ID·내용·위치 스냅샷만 적용.
   이후 들어온 원문은 완료하지 않는다. 질문이 바뀌면 전체 작업을 거절한다.
   대표 답변은 다른 원문으로 자동 전송하지 않는다. 완료는 ‘이해 완료’가 아니다.
4. **공정한 노출**: 가장 오래 기다린 원문부터 페이지·카테고리를 번갈아 최대 5묶음.
   공감 합계는 인원 수가 아니다. 개별 원문 목록과 기존 정렬도 유지한다.
5. **AI 비용 제어**: 모든 신규 질문 자동 답변 생성 대신 강사 선택/명시 재시도만 실행.
   원문 샘플링/폐기 없음. 적응형 샘플링이라고 부르지 않는다.

  stale는 DB 직렬화 오류가 아니라 입력 검증 오류로 반환한다.

- 기존 DB 보존을 위해 reset하지 않았다. 완전히 깨끗한 별도 환경의 전체 migration replay는 미검증.
- 분석 실행 상태는 브라우저 상태이며 재접속 시 ‘위치 미확정’으로 남는다.

- 완료 취소 버튼은 현재 화면의 마지막 성공 요청에 한정된다. 액션 기록은 DB에 남지만
  재로그인 후 이력 조회 UI는 아직 없다. 묶음 답변 전송은 아래 후속 구현 참고.
- 동일 IP 익명 로그인 제한은 현재 `anonymous_users = 30`/시간이다.
  같은 와이파이 100명 입장 실험은 이 제한과 CAPTCHA/남용 방지 정책을 먼저 정해야 한다.
